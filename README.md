# 🛡️ VPS Security Hardening — Interactive Menu

Комплексный интерактивный Bash-скрипт для поэтапной настройки безопасности Linux-сервера.

[![Bash](https://img.shields.io/badge/language-bash-black.svg)](https://www.gnu.org/software/bash/)
[![License](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

**Особенности:**
- 🎯 **Интерактивное меню:** Пошаговая настройка через удобное текстовое меню
- 🛡️ **Hardening:** Продвинутая защита (Fail2Ban, UFW, Auditd, Secure SSH)
- 📊 **Мониторинг:** Детальный статус системы в реальном времени
- 🔄 **Гибкость:** Каждую функцию можно настроить отдельно через подменю
- 📝 **Логирование:** Полное протоколирование всех действий в `/root/security_hardening.log`
- 💾 **Резервное копирование:** Автоматическое создание бэкапов конфигов перед изменениями

## Возможности

### 📊 Главная панель статуса
- Информация о системе (OS, ядро, uptime)
- Мониторинг железа (CPU, RAM, Disk)
- Сетевые интерфейсы и публичный IP
- Конфигурация SSH
- Статус SWAP и Docker
- Состояние служб безопасности

### 🛠 Модули безопасности:

#### 1. ⚙️ Базовая настройка системы
- Изменение Hostname
- Настройка таймзоны
- Создание и управление SWAP-файлом

#### 2. 👥 Управление пользователями (Подменю)
- Создание нового пользователя с sudo
- Добавление/удаление пользователей
- Просмотр информации о пользователе
- Проверка безопасности аккаунтов
- Управление блокировками

#### 3. 🔑 SSH Hardening (Подменю)
- Смена SSH порта
- Настройка аутентификации по ключам
- Тонкая настройка параметров (PermitRootLogin, PasswordAuth и др.)
- Управление списком разрешённых пользователей (AllowUsers)
- Перезапуск службы SSH

#### 4. 🔥 Firewall UFW (Подменю)
- Базовая настройка (открыть SSH, HTTP, HTTPS)
- Открытие/закрытие портов
- Управление правилами (добавление, удаление по номеру)
- Включение/выключение firewall
- Сброс к настройкам по умолчанию
- Настройка логирования (5 уровней)

#### 5. 🛡️ Fail2Ban (Подменю)
- Базовая конфигурация (защита SSH)
- Просмотр заблокированных IP
- Ручная блокировка/разблокировка IP
- Статистика банов за 24 часа
- Тонкая настройка (ban time, max retry, find time, mode)
- Включение/выключение службы

#### 6. 📊 Auditd (Подменю)
- Настройка правил аудита
- Мониторинг системных файлов (`/etc/passwd`, `/etc/shadow`, `/etc/ssh/sshd_config`)
- Поиск событий по ключам (identity, auth, logs)
- Просмотр последних событий
- Добавление собственных правил мониторинга
- Управление службой

#### 7. 📦 Установка пакетов
- Быстрая установка необходимых инструментов безопасности

#### 8. 🧹 Очистка системы
- Удаление ненужных пакетов (autoremove)
- Очистка кэша apt

#### 9. 🔍 RKHunter — Rootkit Detector (Подменю)
- Быстрая проверка на rootkit'ы
- Просмотр результатов проверки
- Обновление базы сигнатур
- Обновление свойств файлов (propupd)
- Полное сканирование системы (10-30 мин)
- Настройка cron и email уведомлений

#### 10. 🔄 Unattended-Upgrades (Подменю)
- Включение/выключение автообновлений
- Просмотр статуса и логов
- Настройка типов обновляемых пакетов
- Ручной запуск обновлений
- История установленных обновлений

## Технологический стек

- **Bash 4.0+** - основная логика автоматизации
- **UFW** - управление firewall
- **Fail2Ban** - защита от brute-force атак
- **Auditd** - система аудита событий безопасности
- **RKHunter** - детектор rootkit'ов
- **Ubuntu/Debian** - поддерживаемые ОС


Скрипт создаёт следующие файлы на сервере:

```
/root/
├── security_hardening.log            # Лог сессии
└── security_backups_TIMESTAMP/       # Резервные копии конфигов
    ├── sshd_config.bak
    ├── sysctl.conf.bak
    ├── fstab.bak
    └── resolved.conf.bak
```

## 🚀 Быстрый старт

### Требования:
1. VPS с **Ubuntu 18.04+** или **Debian 10+**
2. Права **root**
3. Чистая система (рекомендуется)

### Запуск

```bash
# Загрузите скрипт на сервер
scp VPS_Security_Hardening_Menu.sh root@your-server:/root/

# Или скопируйте содержимое вручную
```

```bash
# Запустите скрипт
cd /root
chmod +x VPS_Security_Hardening_Menu.sh
./VPS_Security_Hardening_Menu.sh
```

После запуска вы увидите главное меню:

```
🛡️ VPS SECURITY HARDENING - INTERACTIVE MENU
────────────────────────────────────────────

📊 СТАТУС СИСТЕМЫ:
   Hostname: your-server
   SSH Port: 22
   Firewall: ❌ OFF
   Fail2Ban: ❌ OFF
   Auditd: ❌ OFF
   SWAP: ❌ OFF

МЕНЮ:
   1) 📊 Показать статус системы
   2) ⚙️  Базовая настройка (Hostname, Timezone, SWAP)
   3) 👥 Пользователи системы
   4) 🔑 Настройка SSH
   5) 🔥 Firewall (UFW)
   6) 🛡️ Настройка Fail2Ban
   7) 📊 Настройка Auditd
   8) 📦 Установить пакеты
   9) 🧹 Очистка системы
   10) 🔍 RKHunter (rootkit detector)
   11) 🔄 Unattended-Upgrades
```

### Навигация
- Выберите нужный пункт меню, введя цифру (0-11)
- Для выхода введите `0` или `q`
- В подменю используйте `0` для возврата назад
- Нажмите `Enter` для продолжения после каждой операции

## Рекомендации по настройке

### 🔐 Минимальная конфигурация безопасности:

1. **Настройте SSH** (пункт 4):
   - Смените порт с 22 на нестандартный (например, 2222)
   - Настройте аутентификацию по ключам
   - Отключите вход по паролю

2. **Создайте пользователя** (пункт 3):
   - Добавьте нового пользователя с sudo
   - Заблокируйте root-аккаунт

3. **Включите Firewall** (пункт 5):
   - Используйте базовую настройку (откроет SSH, HTTP, HTTPS)
   - При необходимости добавьте свои порты

4. **Активируйте Fail2Ban** (пункт 6):
   - Примените базовую конфигурацию
   - Добавьте свой IP в белый список

5. **Настройте Auditd** (пункт 7):
   - Примените правила аудита для критических файлов

6. **Включите автообновления** (пункт 11):
   - Активируйте unattended-upgrades для безопасности

### 📋 Регулярное обслуживание:

- Проверяйте статус системы (пункт 1)
- Просматривайте логи Fail2Ban на предмет атак
- Запускайте RKHunter раз в неделю
- Проверяйте события Auditd при подозрительной активности

## Устранение неполадок

### Не могу подключиться по SSH после смены порта
- Убедитесь, что вы используете **новый порт**: `ssh user@ip -p 2222`
- Проверьте, что порт открыт в Firewall

### Firewall заблокировал доступ
- Сбросьте Firewall к настройкам по умолчанию (пункт 5 → 7)
- Подключитесь через консоль провайдера и проверьте правила

### RKHunter показывает предупреждения
- После обновлений системы запустите `propupd` (обновление свойств файлов)
- Проверьте конкретные файлы в логе `/var/log/rkhunter.log`

### Auditd потребляет много ресурсов
- Уменьшите количество правил аудита
- Отключите аудит для менее критичных файлов

## Логи и резервные копии

### Логирование
Все действия записываются в `/root/security_hardening.log`

### Резервные копии
Перед изменениями создаются бэкапы:
- `/root/security_backups_TIMESTAMP/sshd_config.bak`
- `/root/security_backups_TIMESTAMP/sysctl.conf.bak`
- `/root/security_backups_TIMESTAMP/fstab.bak`
- `/root/security_backups_TIMESTAMP/resolved.conf.bak`

### Восстановление
При ошибке скрипт автоматически восстанавливает конфиги из бэкапа.
